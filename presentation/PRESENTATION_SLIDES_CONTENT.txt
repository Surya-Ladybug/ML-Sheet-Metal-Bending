SLIDE 4: SYSTEM ARCHITECTURE
────────────────────────────────────────────────────────────────

Title: Two-Model Approach

Content (Flow Diagram):

  ┌────────────────────┐
  │   USER INPUT       │
  │ • Target Angle     │
  │ • RX Constraint    │
  └─────────┬──────────┘
            │
            ▼
  ┌──────────────────────────────────┐
  │  MODEL 1: Inverse Regression     │
  │  (Target, RX) → (RYR, Radius)    │
  │  GradientBoosting                │
  └─────────┬────────────────────────┘
            │
            ▼
  ┌──────────────────────────────────┐
  │  MODEL 2: Forward Prediction     │
  │  (RX, RYR) → Stable Angle        │
  │  RandomForest                    │
  └─────────┬────────────────────────┘
            │
            ▼
  ┌────────────────────┐
  │   OUTPUT           │
  │ • Stable Angle     │
  │ • Tool Command     │
  │ • Toolpath CSV     │
  └────────────────────┘

What to Say (60 seconds):
  "We use TWO ML models. Model 1 solves the inverse problem:
  given a target angle and RX constraint, what RYR value should
  we use? Model 2 is the forward predictor: given tool parameters,
  what stable angle will we get after tool release?"

SLIDE 6: MODEL 1 - FORWARD PREDICTION
────────────────────────────────────────────────────────────────

Title: RandomForest for Stability Prediction

Content:
  Input:  (RX, RYR)
  Output: Stable part angle after tool release
  
  Algorithm: RandomForestRegressor (100 trees)
  
  Performance:
    • Test MAE: 9.4°
    • Test R²: 0.72
    • Feature Importance:
      - RYR: 78.7%
      - RX: 21.2%
  
  Why RandomForest?
    ✓ Captures complex material behavior
    ✓ No physics assumptions needed
    ✓ Robust to FEM noise

Visual Suggestion:
  Bar chart showing feature importance

What to Say (60 seconds):
  "The forward model uses RandomForest to predict the stable
  angle. RandomForest is ideal here because it captures
  non-linear relationships without requiring constitutive
  equations. The model learns directly from FEM data."

────────────────────────────────────────────────────────────────
SLIDE 7: MODEL 2 - INVERSE DESIGN
────────────────────────────────────────────────────────────────

Title: GradientBoosting for Parameter Selection

Content:
  Input:  (Target Angle, RX)
  Output: (RYR, Inner Radius)
  
  Algorithm: GradientBoostingRegressor (multi-output)
  
  Performance:
    • RYR MAE: 0.30
    • Radius MAE: 4.6mm
  
  Why Inverse is Hard:
    ❌ No analytical solution exists
    ❌ Non-unique (multiple solutions possible)
    ❌ Path-dependent material behavior

Visual Suggestion:
  Diagram showing inverse problem complexity

What to Say (60 seconds):
  "The inverse model predicts required parameters from a
  desired outcome. This is mathematically challenging because
  the forward problem is non-unique - multiple tool configurations
  can produce similar results. ML learns the 'most likely'
  solution empirically."
